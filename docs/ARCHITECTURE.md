# Архитектура

## Принцип: сервер решает всё

```
Клиент (браузер)                      Сервер (Node)
 ввод → Command ── WebSocket /ws ──▶  World.command()  (валидация, ничего не доверяем клиенту)
                                       World.step()     10 раз в секунду
 рендер ◀── Snapshot (JSON) ────────  World.snapshotFor(player) — только то, что игрок видит
```

- `packages/shared` — вся игровая логика. Не зависит от DOM и Node, поэтому её можно запускать на сервере,
  в тестах и (в будущем) на клиенте для предсказания.
- Состояние мира (`WorldState`) — простые данные без классов → `JSON.stringify` = сохранение.
- ГПСЧ детерминирован (`Rng`, состояние сохраняется): одинаковые команды → одинаковый мир.
  Это проверяется тестом «мир из JSON продолжает жить точно так же».

## Файлы ядра

| Файл | Что внутри |
|---|---|
| `defs.ts` | Весь баланс: ресурсы, модули, корпуса, биомы, враги, системы. Менять цифры — здесь |
| `state.ts` | Типы состояния мира |
| `grid.ts` | Сетка и A* |
| `air.ts` | Комнаты (заливка) и воздухообмен |
| `ship.ts` | Создание корабля, энергосеть, жизнеобеспечение, пожары, пробоины, строительство |
| `crew.ts` | ИИ экипажа: потребности, задачи, криосон, важные задачи |
| `world.ts` | Системы, полёт, добыча, бой, враги, торговля, экспедиции, команды, снимки |
| `protocol.ts` | Сообщения клиент ↔ сервер |

## Путь к тысячам игроков

Уже заложено:
- **Граница шарда = звёздная система.** Все сущности живут внутри `StarSystem`, между системами
  перемещается только корабль (гиперпрыжок). Систему можно вынести в отдельный процесс, прыжок станет
  передачей корабля между серверами.
- **Интерес-менеджмент:** снимок содержит только объекты в радиусе сенсоров; планировки кораблей
  отправляются один раз на версию (`ClientCache`).
- **Офлайн-корабли заморожены** — не тратят CPU.

Дальше (по мере роста):
1. Дельта-снимки вместо полных, бинарный формат (MessagePack / собственный).
2. Каждая система — свой worker/процесс; шлюз держит WebSocket и маршрутизирует.
3. Хранилище — Postgres (игроки, кланы) + снимки систем; сейчас это один JSON-файл.
4. Предсказание движения на клиенте (общий код уже в `shared`).
5. Если понадобится клиент на Unity/Godot: он подключается к тому же протоколу, сервер не меняется.
